2. Module 1: Advanced Chunking — src/m1_chunking.py

Giải thích 3 Chiến lược Chunking Nâng cao

Chunking là nền tảng quyết định chất lượng của toàn bộ hệ thống RAG. Cắt đoạn sai sẽ làm mất thông tin hoặc tạo ra các đoạn văn vô nghĩa.

1. Semantic Chunking (chunk_semantic)

Tách văn bản thành các câu riêng biệt, mã hóa từng câu thành embedding qua mô hình all-MiniLM-L6-v2, đo Cosine Similarity giữa 2 câu liên tiếp. Nếu điểm tương đồng < 0.85 thì tách sang chunk mới, giúp gom các câu cùng chủ đề lại với nhau mà không cắt giữa ý.

2. Hierarchical Chunking (chunk_hierarchical)

Chiến lược khuyến nghị cho Production: Tạo ra 2 cấp độ: Parent Chunk (2048 ký tự) chứa toàn bộ đoạn văn/quy định lớn, và Child Chunks (256 ký tự) được gắn kèm parent_id. Khi tìm kiếm, Vector Search sẽ khớp với Child Chunk (độ chính xác cao), nhưng khi đưa vào context cho LLM thì trả về Parent Chunk (ngữ cảnh đầy đủ).

3. Structure-Aware Chunking (chunk_structure_aware)

Sử dụng Regex nhận diện các Header cấp độ Markdown (#, ##, ###) để phân đoạn theo Section. Đảm bảo toàn vẹn các bảng biểu (Markdown tables), danh sách và code blocks mà không bị xé vụn giữa chừng.

src/m1_chunking.py (Trích đoạn Hierarchical) Python 
# Cắt Parent và gán ID liên kết cho Child Chunks
parents: list[Chunk] = []
for para in paragraphs:
    if len(current_parent) + len(para) > parent_size and current_parent:
        pid = f"parent_{len(parents)}"
        parents.append(Chunk(text=current_parent.strip(), metadata={**metadata, "parent_id": pid}))
        current_parent = ""
    current_parent += para + "\n\n"

# Mỗi Child Chunk được liên kết chính xác với parent_id
for parent in parents:
    pid = parent.metadata["parent_id"]
    for seg in segments:
        children.append(Chunk(text=current_child.strip(), metadata=metadata, parent_id=pid))

3. Module 2: Hybrid Search & RRF — src/m2_search.py

Kết hợp BM25 (Sparse) + Qdrant BGE-M3 (Dense) + RRF Fusion

Tìm kiếm kết hợp (Hybrid Search) khắc phục điểm yếu của từng phương pháp riêng lẻ: BM25 bắt chính xác từ khóa và con số, trong khi Dense Search bắt trọn vẹn ngữ nghĩa tương đồng.

Thành phần Class / Hàm Cơ chế & Kỹ thuật hoạt động
Vietnamese Tokenizer segment_vietnamese() Sử dụng thư viện underthesea phân tích ngữ pháp và tách từ ghép tiếng Việt (ví dụ: "nghỉ_phép", "bảo_hiểm_y_tế").
BM25 Okapi BM25Search Lập chỉ mục từ khóa dựa trên tần suất từ (TF-IDF cải tiến). Bắt cực kỳ chuẩn các con số (ví dụ: "30 triệu", "12 ngày") và thuật ngữ viết tắt.
Dense Search DenseSearch Sử dụng mô hình BAAI/bge-m3 (1024 chiều) lập chỉ mục trên Qdrant Vector DB với Cosine Distance. Có sẵn fallback :memory: tự động.
Reciprocal Rank Fusion reciprocal_rank_fusion() Hợp nhất 2 danh sách xếp hạng theo công thức: RRF Score(d) = Σ 1 / (60 + rank + 1).
src/m2_search.py (Thuật toán RRF) Python 
def reciprocal_rank_fusion(results_list: list[list[SearchResult]], k: int = 60, top_k: int = 20):
    rrf_scores: dict[str, dict] = {}
    for result_list in results_list:
        for rank, result in enumerate(result_list):
            if result.text not in rrf_scores:
                rrf_scores[result.text] = {"score": 0.0, "metadata": result.metadata}
            # RRF Formula: Không cần chuẩn hóa phân phối điểm số
            rrf_scores[result.text]["score"] += 1.0 / (k + rank + 1)

    sorted_results = sorted(rrf_scores.items(), key=lambda x: x[1]["score"], reverse=True)[:top_k]
    return [SearchResult(text=text, score=data["score"], metadata=data["metadata"], method="hybrid")
            for text, data in sorted_results]

4. Module 3: Cross-Encoder Reranking — src/m3_rerank.py

Tại sao cần Reranking? (Bi-Encoder vs Cross-Encoder)

Bi-Encoder (trong Dense Search) mã hóa Query và Document riêng rẽ nên mất tương tác từ ngữ sâu. Cross-Encoder đưa trực tiếp cặp (Query, Document) qua toàn bộ các tầng Transformer Self-Attention để chấm điểm tương quan chuẩn xác tuyệt đối.

Mô hình sử dụng chính
BAAI/bge-reranker-v2-m3

Độ chính xác vượt trội, nhận diện ngữ nghĩa tiếng Việt đa tầng. Giảm context từ top-20 xuống top-3.

Phương án thay thế siêu nhẹ
FlashrankReranker (<5ms)

Sử dụng ONNX runtime tối ưu cho production yêu cầu độ trễ cực thấp.

src/m3_rerank.py Python 
class CrossEncoderReranker:
    def __init__(self, model_name: str = "BAAI/bge-reranker-v2-m3"):
        self.model_name = model_name
        self._model = None

    def rerank(self, query: str, documents: list[dict], top_k: int = 3) -> list[RerankResult]:
        if not documents:
            return []
        model = self._load_model()
        # Ghép cặp (Query, Text) để chạy qua Cross-Attention
        pairs = [(query, doc["text"]) for doc in documents]
        scores = model.predict(pairs)
        scored = sorted(zip(scores, documents), key=lambda x: x[0], reverse=True)
        return [RerankResult(text=doc["text"], rerank_score=float(score), rank=i+1)
                for i, (score, doc) in enumerate(scored[:top_k])]

6. Module 5: Enrichment Pipeline — src/m5_enrichment.py

Làm giàu dữ liệu trước khi Embed & Đột phá Single-Call

Làm giàu chunk (Enrichment) giúp giải quyết triệt để 2 vấn đề lớn nhất của RAG: Context Loss (Mất ngữ cảnh nguồn) và Vocabulary Gap (Khoảng cách từ vựng giữa câu hỏi và tài liệu).

1. Contextual Prepend

Gắn 1 câu ngữ cảnh nguồn vào đầu chunk (theo chuẩn Anthropic Contextual Retrieval), giúp vector embedding hiểu chunk nằm ở vị trí nào của tài liệu.

2. Hypothesis Questions (HyQA)

Sinh 2-3 câu hỏi tiềm năng mà chunk có thể giải đáp. Vector của câu hỏi người dùng sẽ cực kỳ gần với vector của câu hỏi sinh sẵn này.

3. Chunk Summarization

Tóm tắt ngắn gọn 2-3 câu giúp loại bỏ các từ đệm và giảm nhiễu ngữ nghĩa (Noise Reduction).

4. Auto Metadata Extraction

Tự động trích xuất topic, thực thể (entities), phòng ban (category) phục vụ Metadata Filtering.

🚀 Kỹ thuật Tối ưu Đạt điểm Bonus: _enrich_single_call()

Thay vì tốn 4 API requests riêng lẻ cho mỗi chunk (dễ dính rate limit 15 RPM của Gemini), hàm _enrich_single_call gom toàn bộ 4 tác vụ trên vào đúng 1 prompt JSON duy nhất, tiết kiệm 75% chi phí và tăng tốc độ xử lý gấp 4 lần.
